cc-token-statusline

A Claude Code status line badge for what a session is actually costing — context window, account quota, cache hit rate and subagent token spend.

Source Changelog Security Issues

Colors move on their own thresholds, so the line changes shape when something needs attention instead of reading the same at 9% and at 82%.

Install

/plugin marketplace add Alfafis/cc-token-statusline
/plugin install cc-token-statusline@cc-token-statusline

Installing the plugin is not enough on its own: Claude Code reads statusLine only from settings.json, and no plugin can register one. The first session after install offers to do the wiring — say yes once and it is done.

What each segment means

SegmentReadsWhy it earns the space
tokenContext window used against the model's limitThe only value that goes down as well as up. Yellow at 60%, red at 85% — you see the wall before hitting it.
cotaBoth account rate limit windows, 5h and 7dAccount-wide, not per session. Once either passes 70% the reset time is appended, since that is the only actionable fact left.
gastoCumulative billed input and output for the sessionConsumption since the start, as opposed to the occupancy token measures.
cacheShare of billed input served from cacheHigher is better. A rate falling through a long session means something large and unstable near the top of the prompt is invalidating the cache each round.
subTokens spent by subagentsFan-out is one line to trigger and its cost appears nowhere else in the interface.
apiTime spent waiting on the APISeparated from wall clock, so a slow session can be blamed on the model or on your own tooling.

How the numbers are obtained

Context, quota, edited lines and API time arrive in the status line JSON payload. Cumulative tokens, cache hit rate and subagent spend do not, so the session transcript is parsed. Two details decide whether that is correct and cheap:

  • Deduplication. Assistant entries repeat once per streamed content block, each copy carrying the full usage object. Summing them blindly overcounts by 2–3×. Every request is counted once, keyed by requestId.
  • Incremental reads. The status line re-renders constantly, so the parse resumes: byte offset and running totals are cached per session, and only new bytes are read. A trailing partial line is left for the next run, because Claude Code appends to that file while the badge renders.

Any error prints nothing and exits 0 — a non-zero exit would hide the entire status bar, so a bug here degrades to an empty badge rather than a broken terminal.

Full breakdown

The badge is a glance. For the numbers behind it, /token-report prints fresh input, cache writes, cache reads, output, thinking tokens and subagent totals for the session.

Configuration

Everything is an environment variable, settable in the env block of settings.json.

VariableDefaultEffect
CC_TOKENS_SEGMENTSctx,quota,tok,cache,sub,lines,apiWhich segments, in order. Add cost for the dollar figure.
CC_TOKENS_WIDTHterminal width − reserveHard cap on badge width. Worth pinning: stdout is a pipe, so terminal size has to be guessed.
CC_TOKENS_RESERVE34Columns left for other badges sharing the line.
CC_TOKENS_COLOR10 disables color. NO_COLOR works too.

When the badge does not fit, segments are dropped in a fixed order: api → lines → sub → gasto → cache → cost → cota → token. Cache outranks the running total on purpose — a hit rate is actionable, a scoreboard is not.

Footprint

  • No network access, no MCP server, no credentials.
  • Reads the local session transcript; writes token counters to ~/.claude/statusline-cache/. No prompt or response content is stored.
  • python3 standard library only, no third-party dependencies.
  • 46 tests on Linux and macOS in CI, plus claude plugin validate --strict on both manifests.
