Privacy Policy

cc-token-statusline, a plugin for Claude Code. Effective 13 August 2026.

Home Source Security

Summary

The plugin collects nothing and transmits nothing. It has no network access, no server, no analytics and no telemetry. Everything it reads and writes stays on your machine, and the author receives no data from your use of it.

What the plugin reads

All of it local, all of it produced by Claude Code on your own machine:

  • The status line JSON payload Claude Code sends it on each render — context window usage, session cost, rate limit percentages, model name, and the path of the session transcript.
  • The session transcript at that path. Only the numeric usage fields of assistant entries are read — token counts and request identifiers. Prompt text, responses, file contents and tool results are not read.
  • Its own cache, described below.
  • settings.json, settings.local.json and combined-statusline.sh, only to test whether the badge is already wired into your status line. The check searches for a filename and nothing else is extracted from those files.

What the plugin stores

Everything lives under ~/.claude/statusline-cache/ (or $CLAUDE_CONFIG_DIR/statusline-cache/ when set). One small file per session, containing:

  • running token counters for the session;
  • the byte offset already parsed in the transcript;
  • the request identifiers already counted, so a request is not counted twice.

Plus a single quota.json, shared by every session, holding the last account rate limit reading seen — the two percentages and their reset timestamps — so /token-report can show them. Claude Code sends those numbers on the status line's stdin and nowhere else, so a report run from a terminal has no other source.

No prompt text, no responses, no file contents, no credentials. Session files are deleted once they go 30 days untouched; quota.json is kept, since it is a single file that is overwritten rather than accumulated. To delete everything the plugin has ever written:

rm -rf ~/.claude/statusline-cache/

scripts/install.py, when you run it, also writes into ~/.claude/hooks/: the badge, the wrapper when an existing status line is being wrapped, cc-token-statusline-chain.json holding that wrapped command, and cc-token-statusline-installed.json holding the version number the copy came from. It adds a statusLine entry to your settings.json and backs up every file it edits. That is a one-time action you invoke; nothing else writes outside the cache directory.

What is never done

  • No network requests, at install time or at runtime.
  • No MCP server is shipped or started.
  • No credentials, API keys or account identifiers are read, stored or transmitted.
  • No third-party dependency — python3 standard library only, so no other party's code runs on your machine through this plugin.
  • Nothing is shared with the author or with anyone else, because nothing leaves your machine.
